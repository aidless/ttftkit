# 查询级分歧率跨跑对照（2026-11-10）

- 数据：三次独立跑（runB / runC / runD），同一组 8 条独立 prompt、seed 基值 1234、
  temperature=0.7、max_tokens=128；全部数字由本脚本从 `*-queries-run*.json` 现算。
- stability 上限 0.2（与 verdict-matrix 单 prompt 拷贝口径同档）。

## 逐跑读数

| 跑次 | c=4 分歧槽位 | c=4 rate | c=16 分歧槽位 | c=16 rate |
| --- | --- | --- | --- | --- |
| runB | [0, 2, 3] | 0.375 | [0, 2, 3, 4] | 0.500 |
| runC | [0, 2, 3] | 0.375 | [0, 2, 3, 4] | 0.500 |
| runD | [0, 2, 3] | 0.375 | [0, 2, 3, 4] | 0.500 |

## c=1 baseline 自身跨跑复现性

- 同一 prompt+seed 在 c=1（无并发批处理）下逐字节一致数：
  - runB/runC: 8/8 一致
  - runB/runD: 8/8 一致
  - runC/runD: 8/8 一致

## 逐 query 翻转频次（同一条 prompt 在 3 跑里被 batch 翻了几次）

- c=4: q0=3/3, q1=0/3, q2=3/3, q3=3/3, q4=0/3, q5=0/3, q6=0/3, q7=0/3
  - 每跑必翻 index=[0, 2, 3]；三跑都不翻 index=[1, 4, 5, 6, 7]
- c=16: q0=3/3, q1=0/3, q2=3/3, q3=3/3, q4=3/3, q5=0/3, q6=0/3, q7=0/3
  - 每跑必翻 index=[0, 2, 3, 4]；三跑都不翻 index=[1, 5, 6, 7]

## 判决：这一档上限能不能用 8 条 query 判

- 六格 rate 范围 0.375–0.500；按 0.2 上限，三跑的 c=4/c=16 全部 FAIL 的有 6/6 格（点估计口径）。
- 但三次跑的是**同一组 8 条 query**，不是 24 条独立 query：样本量按 query 计仍是 8，
  重复跑只量到单轮 batch 时序的抖动，不能把分母乘 3。
- n=8、0/8 的 Wilson 95% 上界 = 0.324 > 0.2；零分歧下要压到 0.2 以下需 n≥16 条**不同** query（gate 的 power 见证同源）。
- 对称地，3/8 的 Wilson 95% 下界 = 0.137（≤ 0.2），4/8 的下界 = 0.215（> 0.2）：
  c=4 的 FAIL 不是「总体 rate 必然超限」的证明，c=16 的 FAIL 才勉强越线。
  gate 的 power 见证只挂 PASS，是 fail-closed 取舍：PASS 放行部署（危险方向）必须带不确定性，
  FAIL 拦截部署只是保守；两种方向的置信界都应由报告自行算出。
- 结论：stability 闸的 PASS/FAIL 是「本轮这 8 条 query 的点估计」，
  不是「总体分歧率 ≤ 上限」的判决；要下后一种结论，先扩到足够多的独立 query 并声明口径。

## 与单 prompt 拷贝口径的关系

- verdict-matrix 的 2/8(c=4)、1/8(c=16) 是同一 query 的槽位翻与不翻，
